## UI=f(state) 定义与解析

1. 精炼定义

UI=f（state）精辟地概括了React的核心设计哲学：用户界面是应用状态的纯函数映射结果

2. 逐一解释公式
   - state:单一数据源，驱动UI变化的唯一事实来源
   - f:(函数)组件，根据state（和props）返回UI描述
   - UI:虚拟DOM,对UI的一种轻量级描述

3. 通过对比凸显其价值

   - 命名式（JQuery）:手动逐步操作（.show(),.addClass()）
   - 声明式（React）：只声明特定状态下UI的样子，React负责更新
   - 强调好处：可预测性、关注点分离

4. （加分项）提及React的工作机制

   state变化->重新执行组件->比较虚拟DOM->高效更新真实DOM

5. （加分项）思想的源头与演进
   - 体现于官方教程《Thinking in React》等
   - 可提及RSC演进带来的UI=f(data,state)模型（注意点到即止）

## 虚拟DOM是如何工作?

- 核心思路：用JS对象模拟DOM，状态变化时，先在JS对象上计算和比较，找出最小差异，然后将这些差异批量更新到真实DOM。
- 关键步骤拆解：
  - 创建/更新虚拟DOM树
  - Diff比较与Reconciliation（调和）
  - 批量更新真实DOM
- 最终效果：显著减少直接操作真实DOM的次数和范围，提升复杂应用下的渲染性能。

- 核心价值：虚拟DOM的核心在于性能优化
- 实现性能优化的途径：
  - 减少DOM操作次数与范围
  - 批量更新（Batching）

- 跨平台能力：
  - 基础：虚拟DOM是JS对象，不直接依赖浏览器环境
  - 应用案例：React Native、服务器端渲染SSR
- 改善开发体验：
  - 编程范式：支持声明式编程，开发者更专注于数据和状态管理。
  - 降低复杂度：框架处理从数据到真实DOM的映射和高效更新，简化UI开发。

## 虚拟DOM的Diff算法工作原理

- 同层比较(Tree Diff)
- 组件类型判断（Component Diff）
  - 元素类型判断（Element Diff）
  - 列表节点的优化与key的重要性

虚拟DOM的缺点或适用边界

- 额外的js计算开销
- 首次渲染的轻微延迟
- 内存占用

## Vite和webpack的区别

webpack的工作模式

核心思想：一切皆模块

- 从入口点递归构建依赖图
- 将所有模块打包成一个或多个bundle文件

问题：开发模式下的瓶颈

开发服务器启动时，需要完成整个项目的遍历、依赖分析、编译和打包

webpack :HMR的优化空间

挑战：

- 文件变化时，仍需判断影响模块并重新构建
- 复杂项目中：HMR响应速度可能不尽人意

根本原因：先打包，再服务的模式

vite的优势

- 启动即服务
  - vite开发服务器几乎瞬间启动，无需预打包

- 工作方式
  - 源码通过浏览器支持的<script type="module">提供
  - 浏览器按需请求模块
  - vite服务器拦截请求，按需编译并提供模块
